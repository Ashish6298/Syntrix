PHASE 2.7 OBJECTIVE
-------------------
  Introduce a production-grade, deterministic Template Validation & Quality
  Assurance Engine operating on raw, resolved, composed, and customized templates
  prior to project generation. Build the subsystem in `lib/src/template/quality/`
  with immutable domain models for findings, reports, profiles (`basic`, `standard`,
  `strict`, `release`), rules, rule registries, and engine evaluators, while reusing
  Phase 1.7 validation infrastructure where appropriate.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. QUALITY ASSURANCE SUBSYSTEM (`src/template/quality/`)
   - TemplateQualityFinding: Structured finding model holding rule ID, category,
     severity (error, warning, info), message, file path, and remediation advice.
   - TemplateQualityProfile: Quality profiles (`basic`, `standard`, `strict`, `release`).
     Applies severity promotion rules in release mode.
   - TemplateQualityReport: Aggregated report model containing findings, error/warning/info
     counts, pass/fail status, and JSON export.
   - TemplateQualityRule & QualityRuleRegistry: Extensible rule contract and registry.
     Rule implementations include ManifestIntegrityRule, PathSecurityRule,
     PlaceholderSyntaxRule, and ConflictCheckRule.
   - TemplateQualityEngine: Core evaluator supporting raw Template, ResolvedTemplate,
     CompositionPlan, and CustomizationPlan evaluation.

2. EXCEPTION HIERARCHY EXTENSION
   - Added TemplateQualityException and TemplateQualityValidationException extending
     TemplateException in `exceptions.dart`.

3. CLI INTEGRATION (`fps template validate`)
   - Added `fps template validate <template-id>` subcommand under TemplateCatalogCommand.
   - Supports `--version`, `--profile`, and `--json` flags.
