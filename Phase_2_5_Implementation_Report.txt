PHASE 2.5 OBJECTIVE
-------------------
  Evolve template composition into a production-grade, deterministic, extensible
  composition system capable of combining a base template with multiple feature
  templates/extensions/layers in a controlled manner, resolving dependencies and
  file conflicts predictably, preserving complete file provenance, validating
  composition compatibility before generation, and producing an immutable resolved
  composite template that can be consumed by the existing generation pipeline
  without requiring changes to the underlying project generator.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. COMPOSITION SUBSYSTEM (`src/template/composition/`)
   - CompositionRequest: Encapsulates base template ID, version constraints,
     ordered extension IDs, conflict policy (fail/override/skip), compatibility
     policy, requested project type, and required capabilities.
   - CompositionLayer: Structured model representing layers in the composition
     stack (Layer 0 = Base, Layer 1..N = Dependencies / Extensions) with layer indices.
   - FileProvenanceRecord & CompositionConflict: Comprehensive auditing models for
     every asset path, tracking source template ID, version, layer index, resolution
     action (created, overridden, skipped), and conflicting sources.
   - CompositionPlan: Immutable preview model exposing total files, override/skip
     counts, layers, conflicts, provenance, and JSON serialization.
   - EnhancedCompositionEngine: Core deterministic composition engine executing
     path security checks (rejecting absolute paths, `..` traversal, and invalid
     separators), dependency solving, compatibility checking, file merging under
     conflict policies, and manifest aggregation.

2. RESOLVER & COMPATIBILITY INTEGRATION
   - Extended CompatibilityAwareResolver to expose `composePlan(CompositionRequest)`.
   - Enhanced TemplateCompositionEngine to delegate to EnhancedCompositionEngine
     under the hood while preserving existing static `compose()` API signature.

3. EXCEPTION HIERARCHY EXTENSION
   - Added TemplateCompositionException, CompositionConflictException, and
     PathSecurityException extending TemplateException in `exceptions.dart`.
   - Ensured zero exposure of file system paths, credentials, or environment details.

4. CLI INTEGRATION (`fps template compose`)
   - Added `fps template compose <base-id> [extension-ids...]` subcommand under
     TemplateCatalogCommand.
   - Supports `--version`, `--conflict-policy`, `--compatibility-policy`, and `--json`.

================================================================================
  SECURITY, SIDE-EFFECT & DETERMINISM VERIFICATION
================================================================================

- Security: All file paths undergo path normalization and strict traversal checks.
  Absolute paths (`/`, `C:\`) and path traversal sequences (`..`) throw PathSecurityException.
- Zero Mutation: All composition operations execute 100% in memory. No disk writes,
  process executions, Git mutations, or network requests occur during resolution or plan preview.
- Determinism: Composition layers follow fixed precedence rules (Base = Layer 0,
  Dependencies/Extensions = Layer 1..N). Results are completely independent of collection iteration order.
