PHASE 2.4 OBJECTIVE
-------------------
  Introduce a production-grade, deterministic, extensible, and testable
  Template Versioning & Compatibility Engine that determines whether a template
  version is compatible with the active SDK environment (Dart & Flutter SDKs),
  operating system / target platform, project archetype, required capabilities,
  and template dependencies before resolution or project generation occurs.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. COMPATIBILITY DOMAIN SUBSYSTEM (`src/compatibility/`)
   - Introduced a dedicated, isolated compatibility module in core.
   - SdkVersionConstraint: Wraps TemplateSemVer for range, caret, exact, and
     wildcard SDK constraint evaluation without duplicating SemVer logic.
   - SdkEnvironment: Abstract injectable provider with mockable implementation
     (MockSdkEnvironment). No direct OS or process execution in tests.
   - CompatibilityIssue & Severity: Immutable, deterministic diagnostic issues
     categorized by axis (dartSdk, flutterSdk, platform, projectType, capability,
     dependency, metadata) and severity (error, warning, info).
   - CompatibilityResult: Aggregated result encapsulating error counts, issue
     lists (sorted deterministically), and environment summaries.
   - CompatibilityPolicy: 4-tier policy matrix (permissive, standard, strict,
     release) controlling evaluated axes and warning promotion.
   - CompatibilityEvaluator: Fixed-order evaluation engine executing checks across
     all 6 compatibility axes deterministically.
   - CompatibilityAwareResolver: Extension of TemplateResolver incorporating
     compatibility filtering and highest-compatible-version selection.

2. EXCEPTION HIERARCHY EXTENSION
   - Added CompatibilityException and InvalidSdkConstraintException extending
     PackageStudioException.
   - Ensured zero leakage of system file paths, environment variables, or
     secrets in exception messages.

3. CLI INTEGRATION (`fps template check`)
   - Added `fps template check <template-id>` subcommand under `fps template`.
   - Supports `--version`, `--dart-version`, `--flutter-version`, `--os`, `--policy`,
     and `--json` flags.
   - Outputs machine-readable JSON or human-friendly formatted reports.
