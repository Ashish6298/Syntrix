PHASE 2.8 OBJECTIVE
-------------------
  Introduce a production-grade, deterministic, extensible, secure, and testable
  Template Hooks & Lifecycle subsystem under `lib/src/template/hooks/` that allows
  templates and template extensions to participate in well-defined lifecycle stages
  before, during, and after project generation without coupling hook implementations
  directly to the existing ProjectGenerator, TemplateResolver, CompositionEngine,
  CustomizationEngine, or CLI command implementations.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. TEMPLATE HOOKS & LIFECYCLE SUBSYSTEM (`src/template/hooks/`)
   - TemplateHookPhase: Deterministic lifecycle stages covering discovery/resolution,
     pre/post resolution, pre/post composition, pre/post customization, pre/post
     generation, validation, completion, and failure phases.
   - TemplateHookPolicy: Execution failure policies (`failFast`, `continueOnError`,
     `warningOnly`).
   - TemplateHookAction: Declarative modifications proposed by hooks (`addFile`,
     `modifyVariable`, `addValidationRequirement`, `addGenerationAction`).
   - TemplateHookContext: Sandboxed, restricted execution context bounded strictly to
     the active target project directory with path sanitization and automatic secret
     redaction.
   - TemplateHookResult & TemplateHookDiagnostic: Structured outcomes capturing status,
     duration, redacted diagnostic logs, and proposed actions.
   - TemplateHookRegistration: Immutable registration record preserving provenance
     and insertion ordering.
   - TemplateHook & FunctionalTemplateHook: Extensible contract and callback wrapper
     for hook definitions.
   - TemplateHookRegistry: Registration validation (unique IDs, supported phases),
     topological dependency graph resolution, priority ordering (descending), and
     circular dependency detection throwing `TemplateHookDependencyException`.
   - TemplateHookEngine: Lifecycle orchestrator handling phase execution, policy-driven
     exception safety, secret redaction, and dry-run zero-mutation guarantees.

2. EXCEPTION HIERARCHY EXTENSION
   - Added `TemplateHookException` and subclasses (`TemplateHookExecutionException`,
     `TemplateHookSecurityException`, `TemplateHookValidationException`,
     `TemplateHookDependencyException`, `TemplateHookTimeoutException`) extending
     `TemplateException` in `exceptions.dart`.

3. CLI INTEGRATION (`fps template hooks`)
   - Added `fps template hooks <template-id>` subcommand under TemplateCatalogCommand.
   - Supports `--version`, `--phase`, `--dry-run`, and `--json` flags.

================================================================================
  SECURITY, SIDE-EFFECT & DETERMINISM VERIFICATION
================================================================================

- Security: All hook filesystem interactions pass through sandboxed SystemHookSandboxFileSystem.
  Absolute paths (`/`, `C:\`) and path traversal sequences (`..`) throw `TemplateHookSecurityException`.
  Tokens, GitHub PATs, Bearer headers, and secrets are automatically redacted from diagnostic output.
- Zero Mutation: Dry-run lifecycle executions operate 100% in-memory without filesystem writes,
  process execution, network requests, Git/GitHub operations, or credential access.
- Determinism: Hook ordering is strictly deterministic via priority descending, stable insertion index,
  and topological graph ordering with circular dependency detection.
