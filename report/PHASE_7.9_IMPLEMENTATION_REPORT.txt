HONEST STATEMENT ON TIMEOUT, ABANDONED FUTURES & ISOLATION GUARANTEES (DART CONCURRENCY MODEL)
-------------------------------------------------------------------------------------------------
  1. Timeout & Abandoned-Future Tail Absorption Guarantee:
     In Dart's single-threaded event loop architecture, the runtime races plugin asynchronous operations against a configurable `Duration` via `Future.timeout`.
     When an invocation exceeds its duration threshold:
       - The runtime immediately returns a `PluginExecutionStatus.timedOut` result to the caller without hanging the calling process.
       - The runtime explicitly attaches a safe background error absorber (`unawaited(pluginFuture.then<void>((_) {}, onError: ...))`) to the losing/abandoned future at the moment the timeout triggers.
       - Any delayed error or unhandled exception subsequently thrown by the abandoned future in the background is safely trapped and logged, completely preventing it from escaping into the isolate/zone or crashing the process at a later time.
     Honest Limitation & Resource Cleanup Decision:
       - Dart cannot forcibly abort or kill synchronous CPU-blocking loops running inside an isolate.
       - Resource Cleanup Decision: For in-flight I/O or network operations (e.g. `CheckedNetworkAccessProxy`), this phase does not inject artificial cancellation signals; in-flight tasks are abandoned fail-closed to complete or fail asynchronously in the background where their results are discarded and any errors safely absorbed.

  2. Fault Isolation Guarantee:
     All plugin contribution invocations are wrapped in structured `try / catch` blocks at the individual plugin boundary (`executeContribution` and `executeBatch`).
     Any unhandled exception, thrown error, or permission denial inside a plugin is trapped, logged, converted into a `PluginExecutionResult` (with status `failed`, `timedOut`, or `permissionDenied`), and never propagates up to crash the core process or interrupt other plugins in a batch.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. EXCEPTIONS (`lib/src/error/exceptions.dart`)
   - `PluginExecutionException`: Base exception for runtime execution errors.
   - `PluginTimeoutException`: Raised when execution exceeds allocated duration.

2. DOMAIN MODELS (`lib/src/plugin/runtime/plugin_execution_models.dart`)
   - `PluginExecutionStatus`: Enum (`success`, `failed`, `timedOut`, `rejectedNotActive`, `unsupportedContribution`, `permissionDenied`).
   - `PluginExecutionResult<T>`: Immutable outcome with `pluginId`, `operation`, `status`, `value`, `errorMessage`, `stackTrace`, `durationMs`, and `timestamp`.
   - `PluginBatchExecutionResult`: Aggregation of per-plugin execution results with summary metrics.
   - `ExecutionAuditRecord`: Timestamped execution log entry.

3. EXECUTION CONTEXT (`lib/src/plugin/runtime/plugin_execution_context.dart`)
   - `PluginExecutionContext`: Constructed fresh per invocation. Supplies scoped checked proxies (`CheckedPackageAnalysisContribution`, `CheckedReleaseWorkflowContribution`, `CheckedCommandContribution`, `CheckedNetworkAccessProxy`, `CheckedServiceContribution`).
   - Prevents bypass of Phase 7.8's `PluginPermissionGate`.

4. EXECUTION RUNTIME (`lib/src/plugin/runtime/plugin_execution_runtime.dart`)
   - `PluginExecutionRuntime`:
     * Validates plugin is in `PluginLifecycleState.active` before execution.
     * Executes single contribution calls and batch calls with full fault isolation.
     * Implements configurable timeout racing with abandoned future tail absorption.
     * Routes repeatedly failing plugins (`consecutiveFailures >= maxConsecutiveFailures`) to `PluginLifecycleState.disabled`.
     * Records timestamped, attributed `ExecutionAuditRecord` entries for every invocation.

5. CLI INTEGRATION (`fps template plugin-exec <plugin-id>`)
   - Added `fps template plugin-exec` subcommand under `TemplateCatalogCommand` supporting `--capability`, `--timeout-ms`, and `--json`.
