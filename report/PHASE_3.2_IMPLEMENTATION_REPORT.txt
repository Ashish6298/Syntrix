PHASE 3.2 OBJECTIVE
-------------------
  Introduce a production-grade, deterministic, plan-first API Documentation Generation
  subsystem capable of extracting public API symbols (classes, methods, functions, enums,
  typedefs, extensions) and doc comments from Dart templates/sources, and rendering
  byte-identical Markdown reference documentation.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. API DOCUMENTATION SUBSYSTEM (`src/documentation/api/`)
   - ApiSymbolKind: Enum for public symbol types (`classSymbol`, `functionSymbol`,
     `enumSymbol`, `typedefSymbol`, `extensionSymbol`, `methodSymbol`, `propertySymbol`).
   - ApiParameter: Parameter model for methods/functions.
   - ApiSymbol: Structured symbol model holding name, kind, signature, docComment,
     deprecation state, parameters, and nested members.
   - ApiDocOptions, ApiDocPlan & ApiDocResult: Immutable plan preview and result models
     with JSON export.
   - ApiExtractor: Extraction engine parsing public `lib/*.dart` templates and sources while
     filtering out private `_` symbols.
   - ApiDocGenerator: Core generator service providing plan-first preview (`planApiDoc`,
     `planFromTemplate`) and deterministic Markdown reference rendering (`generateApiDoc`).

2. EXCEPTION HIERARCHY EXTENSION
   - Added ApiDocGenerationException extending PackageStudioException in `exceptions.dart`.

3. CLI INTEGRATION (`fps template api-docs`)
   - Added `fps template api-docs <template-id>` subcommand under TemplateCatalogCommand.
   - Supports `--version`, `--output`, `--write`, and `--json`.
