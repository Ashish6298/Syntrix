DESIGN FIX SUMMARY (SHUTDOWN FAILURE STRUCTURAL DISTINCTION - OPTION A)
-----------------------------------------------------------------------
  Option Chosen: Option (a) — Introduced explicit `PluginLifecycleState.shutdownFailed` terminal failure state.
  Design Rationale:
    Option (a) was chosen because an unqueryable ambiguity between clean shutdown (`inactive`) and failed shutdown (`inactive` with error log only) would violate the structural safety guarantees required for Phase 7.8 (Sandboxing & Isolation System).
    By routing a throwing `shutdown()` call during `transitionTo(stopping)` directly to `shutdownFailed`, downstreams can query `state == PluginLifecycleState.shutdownFailed` directly without parsing transition logs.
    `shutdownFailed` is registered as a terminal failure state in `PluginLifecycleManager.terminalFailureStates`, preventing silent resurrection back to `active` without an explicit `reattempt()`.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. DOMAIN MODELS (`lib/src/plugin/lifecycle/plugin_lifecycle_models.dart`)
   - `LifecycleTransitionRecord`: Immutable audit trail entry recording `instanceId`, `fromState`, `toState`, `timestamp`, and `reason`.
   - `PluginInstanceRecord`: Per-instance container holding unique `instanceId`, `manifest`, plugin instance reference, current `state`, and `history`.

2. PLUGIN LIFECYCLE MANAGER (`lib/src/plugin/lifecycle/plugin_lifecycle_manager.dart`)
   - Single authority for moving plugin instances through the lifecycle state machine.
   - Enforces explicit legal-transition graph (`discovered` -> `validated`, `validated` -> `registered`, `registered` -> `initialized`, `initialized` -> `active`, `active` -> `stopping`, `stopping` -> `inactive`).
   - Rejects illegal transitions (e.g. `discovered` -> `active` directly, `validated` -> `active`, `inactive` -> `active` without re-initialization) throwing `PluginLifecycleException`.
   - Subsystem Gate Delegation:
     * `transitionTo(validated)`: Invokes Phase 7.1 `PluginContractValidator`. Routes to `invalid` on failure.
     * `transitionTo(registered)`: Invokes Phase 7.3 `PluginRegistry`. Routes to `blocked` on refusal.
     * `transitionTo(initialized)` & `transitionTo(active)`: Genuinely calls Phase 7.2 `PluginLifecycleInterface.initialize()`. Routes to `initializationFailed` if `initialize()` throws.
     * `transitionTo(stopping)` & `transitionTo(inactive)`: Genuinely calls Phase 7.2 `PluginLifecycleInterface.shutdown()`. Routes to `inactive` on clean shutdown, or `shutdownFailed` if `shutdown()` throws.
   - Per-Instance State Isolation: State is tracked per `instanceId`, preventing leaks between instances of the same plugin ID.
   - Terminal State Resurrection Guard: Prevents silent direct resurrection from terminal failure states (`invalid`, `incompatible`, `blocked`, `initializationFailed`, `shutdownFailed`, `disabled`) to `active` without explicit `reattempt()` from `discovered`.

3. CLI INTEGRATION (`fps template plugin-lifecycle-status`)
   - Added `fps template plugin-lifecycle-status` subcommand under `TemplateCatalogCommand` supporting terminal summary output and `--json` output.
