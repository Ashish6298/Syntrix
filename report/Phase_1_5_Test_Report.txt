--------------------------------------------------------------------------------
2. ARCHITECTURE & SUBSYSTEM CAPABILITIES
--------------------------------------------------------------------------------
- Domain Model & Configuration (`ExampleOptions`):
  Immutable domain configuration specifying example directory name (`example/`), app name (`<pkg>_example`),
  org name, description, template ID, relative package path (`../`), platform folders, and test flags.
- Template System & Registry (`ExampleTemplate` & `ExampleTemplateRegistry`):
  Extensible template registry providing default runnable Flutter templates (`standard`, `minimal`).
  Generates `lib/main.dart` demonstrating package usage and `test/widget_test.dart`.
- Flutter Process Service Abstraction (`FlutterProjectService`):
  Abstracted Flutter CLI runner (`SystemFlutterProjectService`) supporting `isFlutterInstalled()`
  and `pubGet()`. Injectable and mockable in unit tests.
- Deterministic In-Memory Planning (`ExampleGenerationPlan` & `ExampleAction`):
  Inspectable non-mutating generation plan suitable for `--dry-run` simulation mode.
- Post-Generation Structural Integrity Validation (`ExampleProjectValidator`):
  Inspects generated example app and verifies `pubspec.yaml`, `lib/main.dart`, and safe relative package
  path dependency resolution (`path: ../`).
- Path Security & Boundary Protection:
  `_sanitizePath` enforces that all generated example files resolve strictly inside the example root directory,
  rejecting absolute path overrides and `../` path traversal attacks.
