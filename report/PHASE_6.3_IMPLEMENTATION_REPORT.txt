PHASE 6.3 OBJECTIVE
-------------------
  Introduce a production-grade, deterministic, plan-first Git Tagging & Release Branching
  subsystem under `flutter_package_studio_core` that inspects Git repository state, validates
  release tags and release branch rules, detects existing/conflicting tags or branches, rejects dirty
  working trees, plans release operations through immutable domain models, and isolates actual Git execution
  behind a controlled process-execution abstraction with safe preview/dry-run default behavior.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. GIT TAGGING & RELEASE BRANCHING SUBSYSTEM (`src/release/git/`)
   - GitReleaseState: Model representing snapshot state of a Git repository (current branch, commit hash, cleanliness status, existing tags, existing branches).
   - GitReleaseOptions, GitReleasePlan & GitReleaseResult: Domain models holding options, plans, Markdown report rendering, and JSON export.
   - GitProcessRunner & MockGitProcessRunner: Controlled process-execution abstraction for inspecting state and creating tags/branches in isolation.
   - GitReleaseManager: Core manager service for repository state inspection, conflict detection, release planning, dirty tree rejection, and execution.

2. EXCEPTION HIERARCHY EXTENSION
   - Added GitReleaseException extending PackageStudioException in `exceptions.dart`.

3. CLI INTEGRATION (`fps template git-release <template-id>`)
   - Added `fps template git-release <template-id>` subcommand under TemplateCatalogCommand.
   - Supports `--version`, `--tag`, `--branch`, `--execute`, `--output`, `--write`, and `--json`.
