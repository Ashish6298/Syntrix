## 5. Key Engineering Decisions & Invariants

### 5.1 Project-Scoped Knowledge vs. Personal Memory
As required by the milestone specification, all knowledge memory is strictly scoped to the repository (`.fps/memory/sessions.json`). It retains only project-level engineering facts, architectural decisions, limitations, and defect histories — avoiding personal user memory or arbitrary state.

### 5.2 8 Specialized Knowledge Entry Types
The subsystem supports 8 dedicated engineering knowledge categories:
1. `decision` — Formal engineering and design choices.
2. `limitation` — Documented bounds, constraints, and known system limitations.
3. `architecture` — Subsystem boundaries, architectural patterns, and structural rules.
4. `bug` — Known, tracked, and resolved defects.
5. `releaseHistory` — Release transitions and changelog milestones.
6. `testHistory` — Test execution records, benchmarks, and regression suites.
7. `implementationReport` — Milestone and phase implementation reports.
8. `repeatedIssue` — Recurring pitfalls, flaky dependencies, and repeated issues.

### 5.3 Deterministic Conflict Detection
When recording a new knowledge entry, the engine cross-references existing entries across all sessions in the workspace. If high topic overlap is detected alongside contradicting statements (e.g. opposing requirements, adoption vs. rejection keywords), a `ConflictReport` is generated with a `critical` or `warning` severity rating.

### 5.4 Grounded Evidence References
Every `KnowledgeEntry` supports multiple `EvidenceReference` items that anchor assertions directly to concrete files, line ranges, or documents in the monorepo workspace.

### 5.5 Expiration & Clean Versioning
Entries support optional `expiresAt` timestamps. Expired entries are filtered out of standard queries by default, and `purgeExpired()` allows clean batch removal of obsolete records. Entries can also spawn bumped versions via `createUpdatedVersion()`.

### 5.6 Non-Negotiable Secret Redaction
All ingested text, persisted JSON storage files, query responses, and rendered markdown documents undergo automated secret scrubbing via `SecretRedactor` to prevent credential exposure.
