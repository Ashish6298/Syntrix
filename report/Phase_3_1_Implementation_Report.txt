PHASE 3.1 OBJECTIVE
-------------------
  Introduce a production-grade, deterministic, plan-first README Generation subsystem
  capable of synthesizing professional `README.md` documentation for Flutter packages/projects
  from structured template metadata. Create a dedicated core documentation subsystem under
  `lib/src/documentation/readme/` with immutable domain models, section registries,
  sanitization/redaction rules, plan-first generator services, and CLI subcommand integration.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. README DOCUMENTATION SUBSYSTEM (`src/documentation/readme/`)
   - ReadmeSanitizer: Sanitizes user-provided text, escapes script tags, and redacts secret tokens.
   - ReadmeBadge: Badge domain model with Markdown serialization.
   - ReadmeSection: Section domain model with Markdown heading formatting.
   - ReadmeGenerationOptions: Configuration model for package name, description, version,
     platforms, features, badges, license, and provenance.
   - ReadmeGenerationPlan & Result: Immutable plan preview and result models with JSON export.
   - ReadmeSectionRegistry: Constructs standard ordered sections (Overview, Features, Platforms,
     Installation, Usage, License, Provenance).
   - ReadmeGenerator: Core generator service providing plan-first preview (`planReadme`)
     and deterministic Markdown rendering (`generateReadme`).

2. EXCEPTION HIERARCHY EXTENSION
   - Added ReadmeGenerationException extending PackageStudioException in `exceptions.dart`.

3. CLI INTEGRATION (`fps template readme`)
   - Added `fps template readme <template-id>` subcommand under TemplateCatalogCommand.
   - Supports `--version`, `--output`, `--write`, and `--json`.
