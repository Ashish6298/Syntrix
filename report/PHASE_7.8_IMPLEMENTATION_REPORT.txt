SECURITY BOUNDARY SCOPE STATEMENT (HONEST SCOPE DECLARATION)
------------------------------------------------------------
  Enforced Boundary Scope:
    This phase enforces permission-checked access strictly at the **Core-API Boundary** (`PluginPermissionGate` & Checked Contribution Proxies).
    The core refuses to hand over resources, invoke contributions, or grant CLI command capabilities to plugins that do not hold matching declared and approved permissions.
  Out of Scope Boundary:
    This phase does **NOT** construct operating-system level sandboxing (cgroups, OS process isolation, memory address space separation).
    A malicious plugin bypassing the core API surface via lower-level platform calls (e.g. `Platform.environment`, raw socket opening outside core proxies) is outside this phase's boundary.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. DOMAIN MODELS (`lib/src/plugin/permission/plugin_permission_models.dart`)
   - `PluginPermission`: Closed enum covering all 10 core capability permissions with canonical dot-notation wire format helpers.
   - `PermissionAuditRecord`: Immutable log entry capturing `pluginId`, `permissionName`, `operationAttempted`, `isGranted`, and `reason`.
   - `PermissionStatusSummary`: Map capturing `✓`/`✗` roadmap status items per permission.

2. PLUGIN PERMISSION GATE (`lib/src/plugin/permission/plugin_permission_gate.dart`)
   - Single authority for permission grants (`approvePermission`), audit logging (`_auditLog`), and runtime check (`check()`).
   - Enforces Three-Stage Permission Model:
     1. **Declared**: Present in `manifest.securityRequirements.permissions`.
     2. **Approved**: Explicitly granted in `_approvedPermissions[pluginId]`.
     3. **Enforced**: `check()` requires `isDeclared && isApproved`.
   - Posture: **Deny-by-Default**. Zero approval records or un-declared requests are strictly refused.

3. CHECKED CONTRIBUTION PROXIES (`lib/src/plugin/permission/plugin_contribution_proxies.dart`)
   - Wraps Phase 7.2 contribution interfaces (`PackageAnalysisContribution`, `ReleaseWorkflowContribution`, `CommandContribution`) to gate invocations at the core boundary.
   - Prevents self-reporting plugin code from bypassing checks.

4. LIFECYCLE MANAGER INTEGRATION (`lib/src/plugin/lifecycle/plugin_lifecycle_manager.dart`)
   - Integrated `PluginPermissionGate` check during `transitionTo(registered)`.
   - Plugins carrying declared permissions that are unapproved are blocked during registration and cannot reach `Initialized` or `Active`.

5. CLI INTEGRATION (`fps template plugin-permissions <plugin-id>`)
   - Added `fps template plugin-permissions` subcommand printing roadmap-style `✓`/`✗` status tables and JSON output (`--json`).
