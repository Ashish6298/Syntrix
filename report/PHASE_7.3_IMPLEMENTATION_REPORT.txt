  Implement Phase 7.3 — Plugin Registry for Flutter Package Studio, serving as the central source of truth for all installed/known plugins.
  Enforce the critical safety guarantee: "Registration must NEVER imply execution". Successfully registering a plugin does not invoke `initialize()` or run any code. Activation requires explicit `activatePlugin()` call.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. EXTENDED PLUGIN REGISTRY SUBSYSTEM (`src/plugin/interface/plugin_registry.dart`)
   - Registration vs Activation: Separated `registerPlugin()` (pure inventory/gating) from `activatePlugin()` (explicit lifecycle invocation).
   - Duplicate-ID Protection: `registerPlugin()` refuses duplicate registration by default. Requires explicit `updatePlugin()` to replace.
   - Graceful Unregistration: `unregisterPlugin(id)` removes plugin cleanly from inventory and capability queries without throwing errors on nonexistent IDs.
   - Query & Compatibility Surface: Implemented `exists(id)`, `findPlugin(id)`, `listPlugins()`, `queryPluginsByCapability(capability)`, and `checkCompatibility(id, apiVersion)`.
   - Single Source of Truth: Holds direct `RegisteredPlugin` references, delegating validation to Phase 7.1 and gating to Phase 7.2.

2. CLI INTEGRATION (`fps template plugin-list`)
   - Added `fps template plugin-list` subcommand under TemplateCatalogCommand to list all registered plugins in the central inventory.
