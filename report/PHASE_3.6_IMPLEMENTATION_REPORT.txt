PHASE 3.6 OBJECTIVE
-------------------
  Introduce a production-grade, deterministic, plan-first Screenshot Management
  subsystem capable of defining, discovering, validating, organizing, and managing
  screenshot galleries and manifests for generated Flutter packages and their documentation.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. SCREENSHOT MANAGEMENT SUBSYSTEM (`src/documentation/screenshots/`)
   - ScreenshotCategory: Supported screenshot categories (`overview`, `feature`, `usage`, `workflow`, `platform`, `custom`).
   - ScreenshotItem: Domain model representing screenshot metadata (`id`, `title`, `path`, `category`, `description`).
   - ScreenshotOptions, ScreenshotPlan & ScreenshotResult: Immutable preview plan and
     rendered Markdown gallery output models with JSON export.
   - ScreenshotValidator: Validation engine checking image formats (`.png`, `.jpg`, `.jpeg`, `.svg`, `.webp`),
     relative path requirements, path traversal (`..`) prevention, and duplicate ID prevention.
   - ScreenshotManager: Core manager service rendering clean, deterministic Markdown screenshot galleries.

2. EXCEPTION HIERARCHY EXTENSION
   - Added ScreenshotManagementException extending PackageStudioException in `exceptions.dart`.

3. CLI INTEGRATION (`fps template screenshots <template-id>`)
   - Added `fps template screenshots <template-id>` subcommand under TemplateCatalogCommand.
   - Supports `--version`, `--category` (`overview`, `feature`, etc.), `--output`, `--write`, and `--json`.
