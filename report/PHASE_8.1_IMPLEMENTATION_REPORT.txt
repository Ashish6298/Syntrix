1. DETERMINISM BOUNDARY & ARCHITECTURAL FOUNDATION
────────────────────────────────────────────────────────────────────────────────
Phase 8.1 establishes the foundational architecture for the AI Assistant subsystem.
A core architectural principle of Milestone 8 is the strict formal definition of the
Determinism Boundary:

1. Raw AI Provider Response Exemption:
   - The raw generated text content from an AI provider (e.g. Gemini, OpenAI, Claude)
     is explicitly exempted from determinism guarantees.
   - Downstream consumers must unconditionally treat raw provider responses as
     untrusted, unverified input that must undergo schema parsing and validation.

2. Guaranteed Deterministic Subsystems:
   - Context Assembly: Template metadata, environment tags, capabilities, and dependencies
     are assembled, sorted canonically, and serialized deterministically.
   - Prompt Construction: Given identical inputs, prompt text is byte-identical.
   - Redaction: Bearer tokens, GitHub PATs, and Google API keys are deterministically
     sanitized from prompts and context prior to provider transmission.
   - Output Structuring & Parsing: Strict JSON schema extraction, validation, and coercion
     into typed `AssistantResponse` domain objects (`AnalysisPayload`, `RecommendationPayload`,
     `ExplanationPayload`, `PlanningPayload`).
   - Dual-Format Rendering: Pure, deterministic rendering of `AssistantResponse` into both
     structured JSON and formatted Markdown.
   - Fallback & Error Containment: Fail-closed structured error responses (`providerUnavailable`,
     `invalidResponse`, `timedOut`, `disabled`, `rejected`) with zero caller crashes.

3. Genuine Provider Abstraction:
   - `AiProvider` is an abstract interface defining `checkHealth()` and `complete(AiCompletionRequest)`.
   - `MockAiProvider` is a genuine, swappable implementation supporting configurable canned
     responses, fault injection, delays, and call history tracking without real network calls.

4. Architectural Safety Boundaries:
   - The AI Assistant subsystem is pure request/response computation plumbing.
   - It is structurally incapable of writing files (except when the CLI explicitly passes `--write`
     to save its own rendered output), executing shell commands, publishing packages, or
     running Git operations.
