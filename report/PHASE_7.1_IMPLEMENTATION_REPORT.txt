PHASE 7.1 OBJECTIVE
-------------------
  Implement Phase 7.1 — Plugin Domain Model & Contract Foundation for Flutter Package Studio, formally defining what qualifies as a valid plugin as a pure data-modeling and validation problem.
  Create a `PluginContract` domain model under `flutter_package_studio_core` representing immutable value objects (`PluginId`, `PluginName`, `PluginDescription`, `PluginAuthor`, `PluginCapability`, `PluginLifecycleState`, `PluginCompatibility`, and `PluginManifest`).
  Enforce 100% non-executable contract validation: zero dynamic code loading, zero process execution, zero file mutation, multi-violation discovery, shared SemVer reuse, and deterministic JSON serialization.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. PLUGIN CONTRACT SUBSYSTEM (`src/plugin/contract/`)
   - PluginId, PluginName, PluginDescription, PluginAuthor, PluginCompatibility: Validated immutable value objects enforcing character rules, non-empty constraints, and min <= max range constraints.
   - PluginCapability: Enumerable closed set of recognized capability kinds (`releasePlanning`, `versionManagement`, `changelogGeneration`, `securityAudit`, `artifactGeneration`, `customValidation`).
   - PluginLifecycleState: Closed static enum (`discovered`, `validated`, `incompatible`, `disabled`) with zero execution states.
   - PluginManifest: Immutable composite manifest object supporting deterministic round-trip JSON serialization.
   - PluginContractValidator: Multi-violation validator evaluating untrusted raw manifest JSON maps without executing code.

2. EXCEPTION HIERARCHY EXTENSION
   - Added PluginContractException extending PackageStudioException in `exceptions.dart`.

3. CLI INTEGRATION (`fps template plugin-validate <manifest-json-or-file>`)
   - Added `fps template plugin-validate` subcommand under TemplateCatalogCommand to validate raw plugin manifests from CLI.
