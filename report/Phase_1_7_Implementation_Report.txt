2. ARCHITECTURE & SUBSYSTEM CAPABILITIES
--------------------------------------------------------------------------------
- Immutable Domain Models (`ValidationModels`):
  Defines `ValidationSeverity` (`info`, `warning`, `error`), `ValidationCategory` (11 categories), `ValidationIssue`,
  `ValidationRequest`, `ValidationResult`, `ValidationSummary`, and `ValidationReport` with JSON serialization support.
- Composable Rule Contract & Registry (`ValidationRule` & `ValidationRuleRegistry`):
  `ValidationRule` interface for defining independent checks. `ValidationRuleRegistry` manages rule registration
  and deterministic profile resolution (`basic`, `standard`, `strict`, `release`).
- Tooling Abstraction (`DartToolService` & `SystemDartToolService`):
  Injectable process wrapper for executing system `dart analyze` and `dart test` checks cleanly.
- Pluggable Rule Collections (`rules/`):
  - `PackageStructureRule` (`STRUCT_001`): Verifies required directories and `pubspec.yaml`.
  - `PubspecValidationRule` (`PUBSPEC_001`): Verifies package name, version, and environment bounds.
  - `SecurityValidationRule` (`SEC_001`): Detects exposed GitHub tokens or secrets.
  - `ExampleValidationRule` (`EX_001`): Verifies example directory structure and safe relative `path: ../` dependencies.
  - `RepositoryAssetRule` (`REPO_001`): Verifies repository assets (`README.md`, `LICENSE`).
- Validation Engine Orchestrator (`ValidationEngine`):
  Runs selected rules against target directory without writing to disk (0 filesystem mutations guaranteed).
- Report Rendering Abstraction (`ValidationReporter`):
  Provides `TextValidationReporter` for CLI display and `JsonValidationReporter` for machine-readable JSON output.
- CLI Integration (`AuditCommand`):
  Wired `AuditCommand` with `--target`, `--profile`, and `--json` flags to trigger `ValidationEngine` and return CI exit codes.
