1. HISTORICAL STATE (Phases 7.1–7.9):
   During incremental development across Milestone 7, plugin commands were temporarily scattered under the `fps template` command group as `plugin-*` subcommands:
   - `fps template plugin-validate`
   - `fps template plugin-capabilities`
   - `fps template plugin-list`
   - `fps template plugin-discover`
   - `fps template plugin-config-validate`
   - `fps template plugin-deps-resolve`
   - `fps template plugin-lifecycle-status`
   - `fps template plugin-permissions`
   - `fps template plugin-exec`

2. NEW DEDICATED NAMESPACE (`fps plugin <subcommand>`):
   Consolidated all plugin functionality into the top-level `PluginCatalogCommand` (`fps plugin`), introducing exactly the roadmap's 7 canonical subcommands:
   - `fps plugin list`                  : List all registered/tracked plugins in inventory.
   - `fps plugin discover <dirs...>`    : Scan directory roots for plugin manifests with zero code execution.
   - `fps plugin info <plugin-id>`      : Display detailed identity, version, capabilities, dependencies, and configuration schema.
   - `fps plugin validate <input>`      : Validate raw plugin manifest JSON or file against contract rules with zero code execution.
   - `fps plugin enable <plugin-id>`    : Execute validated lifecycle activation sequence (`discovered` -> `validated` -> `registered` -> `initialized` -> `active`).
   - `fps plugin disable <plugin-id>`   : Perform administrative lifecycle transition to `disabled`.
   - `fps plugin inspect <plugin-id>`   : Comprehensive deep-dive aggregating manifest, lifecycle state, permission model (✓/✗), dependencies, schema, and audit logs.

3. CONSOLIDATION MAPPING & DEPRECATION DECISION:
   - `fps template plugin-validate`        → Replaced by `fps plugin validate`
   - `fps template plugin-list`            → Replaced by `fps plugin list`
   - `fps template plugin-discover`        → Replaced by `fps plugin discover`
   - `fps template plugin-capabilities`    → Replaced by `fps plugin info` / `fps plugin inspect`
   - `fps template plugin-config-validate` → Replaced by `fps plugin validate` / `fps plugin inspect`
   - `fps template plugin-deps-resolve`    → Replaced by `fps plugin discover` / `fps plugin inspect`
   - `fps template plugin-lifecycle-status`→ Replaced by `fps plugin inspect` / `fps plugin enable`
   - `fps template plugin-permissions`     → Replaced by `fps plugin inspect` / `fps plugin info`
   - `fps template plugin-exec`            → Replaced by `fps plugin enable` + runtime execution engine

   *Deprecation Decision Justification*:
   To preserve 100% backward compatibility for existing external automation and tests while guiding users toward the clean `fps plugin` namespace, the old subcommands under `fps template` are retained as functioning **deprecated aliases**, visibly marked with `[DEPRECATED: Use 'fps plugin <cmd>' instead]` in their help descriptions and logging.

4. NON-REGRESSION GUARANTEE:
   No commands outside the plugin domain (`fps template version`, `version-plan`, `changelog`, `git-release`, `publish`, etc.) were renamed, altered, or impacted in any way.
