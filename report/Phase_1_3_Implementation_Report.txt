2. COMPONENT HIGHLIGHTS & ARCHITECTURE
--------------------------------------------------------------------------------
- TemplateManifest & VariableDefinition:
  YAML/JSON manifest parsing with strict schema validation. Defines ID, name, description, version, projectType, SDK constraints, supported platforms, input variables, directory patterns, and file template maps.
- TemplateRegistry:
  Thread-safe in-memory template registry supporting registration, unregistration, ID retrieval, query search, and projectType filtering.
- TemplateContext & Normalization:
  Converts WizardContext into normalized variable keys including snake_case (`package_name`), PascalCase (`package_name_pascal`), camelCase (`package_name_camel`), organization, author, email, current date (`current_year`, `current_date`), and boolean flags (`is_flutter`, `is_dart`).
- TemplateRenderer & TemplateCondition:
  Fast text and path template placeholder substitution (`{{var}}`) supporting optional strict mode. Safe condition evaluator supporting key presence, negation (`!flag`), equality (`key == val`), and inequality (`key != val`).
- GenerationPlan & GenerationAction:
  Deterministic in-memory project generation preview plan allowing full inspection of creation, overwrite, skip, and directory actions prior to filesystem mutation.
- ProjectGenerator & Path Traversal Sanitization:
  Executes generation plans against mockable FileUtils. Enforces path traversal protection ensuring all generated files resolve strictly within the target root directory (`_sanitizePath`). Supports OverwritePolicies (`fail`, `skip`, `overwrite`).
- BuiltinTemplates & CLI Integration:
  Provides the default `flutter_package` template bundle and seamlessly wires `CreateCommand` to run `ProjectGenerator` with interactive, non-interactive, `--dry-run`, and `--overwrite` support.
