PHASE 7.2 OBJECTIVE
-------------------
  Implement Phase 7.2 — Plugin Interface & Capability System for Flutter Package Studio, building directly on Phase 7.1's `PluginManifest`/`PluginCapability` contract.
  Define narrow, purpose-specific abstract Dart contribution interfaces (`PluginLifecycleInterface`, `CommandContribution`, `ServiceContribution`, `ValidationContribution`, `ReleaseWorkflowContribution`, `PackageAnalysisContribution`).
  Build `PluginCapabilityGate` enforcing strict manifest-to-interface authorization and `PluginRegistry` for capability-indexed registration, query surface, and pre-execution lifecycle gating.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. PLUGIN INTERFACE SUBSYSTEM (`src/plugin/interface/`)
   - PluginLifecycleInterface: Base lifecycle interface (`initialize(context)`, `shutdown()`) with idempotent-safe semantics.
   - Contribution Interfaces: Narrow extension points (`CommandContribution`, `ServiceContribution`, `ValidationContribution`, `ReleaseWorkflowContribution`, `PackageAnalysisContribution`).
   - PluginCapabilityGate: Bi-directional authorization gate verifying declared manifest capabilities against implemented code interfaces.
   - PluginRegistry: Capability-indexed registry enforcing Phase 7.1 contract validation, capability authorization, query surface, and safe lifecycle execution.

2. EXCEPTION HIERARCHY EXTENSION
   - Added PluginCapabilityException and PluginRegistrationException extending PackageStudioException in `exceptions.dart`.

3. CLI INTEGRATION (`fps template plugin-capabilities <plugin-id-or-json>`)
   - Added `fps template plugin-capabilities` subcommand under TemplateCatalogCommand to query authorized capabilities matching roadmap output structure.
