2. ARCHITECTURE & SUBSYSTEM CAPABILITIES
--------------------------------------------------------------------------------
- Domain Model & Configuration (`GitHubOptions`):
  Immutable configuration for GitHub repository creation, visibility (`public`/`private`), default branch (`main`),
  homepage URL, topics, feature flags, remote name (`origin`), and auto-push preferences.
- Credential Provider & Secret Redaction (`GitHubCredentialProvider`):
  `EnvironmentGitHubCredentialProvider` discovers tokens via `GITHUB_TOKEN` / `GH_TOKEN` environment variables.
  Includes `redactSecrets()` utility to ensure tokens are never logged or stored in diagnostic payloads.
- API Service Abstraction & Mocks (`GitHubService` & `MockableGitHubService`):
  Decoupled interface for GitHub REST API operations. Unit and integration tests rely on `MockableGitHubService`
  preventing live network mutations during test execution.
- Deterministic Metadata Builder (`GitHubMetadataBuilder`):
  Sanitizes, normalizes, deduplicates, and formats GitHub repository topics and metadata from `TemplateContext`.
- Plan-First System (`GitHubRepositoryPlan` & `GitHubAction`):
  Supports deterministic previewing of remote creation, topic configuration, remote setup, commit staging, and push.
  Guarantees `--dry-run` performs 0 remote mutations or local Git writes.
- Master Orchestrator (`GitHubRepositoryGenerator`):
  Coordinates parameter validation, plan building, API repository creation, local Git remote configuration, initial commit,
  and safe non-destructive remote push via `GitService`.
- Exception Hierarchy (`GitHubException` Family):
  Dedicated error types (`GitHubAuthenticationException`, `GitHubAuthorizationException`, `GitHubNetworkException`,
  `GitHubRepositoryExistsException`, `GitHubConfigurationException`) mapping GitHub API & remote failures cleanly.
