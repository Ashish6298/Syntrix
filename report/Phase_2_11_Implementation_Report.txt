PHASE 2.11 OBJECTIVE
--------------------
  Introduce a production-grade, deterministic, plan-first Template Upgrade & Migration
  subsystem capable of detecting originating project metadata, resolving ordered
  migration chains across SemVer versions, previewing planned steps and file actions
  without disk mutation, safely executing transformations with atomic backup and
  rollback support under explicit conflict policies (`fail`, `preserve`, `overwrite`, `skip`),
  and producing complete auditable migration reports without mutating host environments or
  destroying backward compatibility.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. MIGRATION SUBSYSTEM (`src/template/migration/`)
   - TemplateMigrationFileSystem: Injectable filesystem abstraction (MemoryMigrationFileSystem)
     for isolated testing without operating on the real workspace filesystem.
   - TemplateMigrationAction: Discrete file/metadata action model (`createFile`, `updateFile`,
     `renameFile`, `deleteFile`, `updateMetadata`, `updateDependency`).
   - TemplateMigrationStep: Single version step in a migration chain (e.g. `1.0.0` -> `1.1.0`).
   - TemplateMigrationPlan: Immutable preview plan with total action count, step sequence,
     findings, and JSON export.
   - TemplateMigrationResult: Execution result containing action status, rollback status,
     and findings.
   - TemplateMigrationRequest: Parameter container for migration planning.
   - TemplateMigrationProfile & ConflictPolicy: Profiles (`basic`, `standard`, `strict`,
     `release`) and policies (`fail`, `preserve`, `overwrite`, `skip`).
   - TemplateMigration & SimpleTemplateMigration: Abstract migration contract and declaration model.
   - TemplateMigrationRegistry: Registers migrations and resolves ordered migration chains.
   - TemplateMigrationEngine: Core engine providing metadata detection (`.fps/template_metadata.json`),
     dry-run migration planning, path-security verification, atomic backup creation, execution,
     and automatic rollback upon failure.

2. EXCEPTION HIERARCHY EXTENSION
   - Added TemplateMigrationException, TemplateMigrationConfigurationException,
     TemplateMigrationPlanningException, TemplateMigrationConflictException,
     TemplateMigrationSecurityException, TemplateMigrationExecutionException, and
     TemplateMigrationRollbackException to `exceptions.dart`.

3. CLI INTEGRATION (`fps template migrate`)
   - Added `fps template migrate <target>` subcommand under TemplateCatalogCommand.
   - Supports `--from`, `--to`, `--profile`, `--conflict-policy`, `--dry-run`, `--execute`, and `--json`.
