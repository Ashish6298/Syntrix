1. OBJECTIVE & ARCHITECTURAL OVERVIEW
────────────────────────────────────────────────────────────────────────────────
Phase 8.2 establishes the dedicated Project Context & Codebase Intelligence
subsystem under `packages/flutter_package_studio_core/lib/src/ai/context/` and
integrates it into the CLI via `fps project context` and `fps project`.

The fundamental objective is teaching the AI Assistant *what to look at* before
it ever prompts an AI provider, adhering strictly to the non-execution precedent
established in Phase 7.4 plugin discovery:

- The engine reads monorepo structure, individual Flutter/Dart packages, `pubspec.yaml`,
  source, test, documentation, existing reports, configuration files, package dependencies,
  and release infrastructure attributively and defensively as plain text.
- It NEVER imports, compiles, evaluates, or executes project source code.
- A mandatory, fail-closed `SensitiveFileFilter` evaluates every candidate file before
  it can enter context assembly, structurally preventing `.env*`, `.pem`/`.key`/`id_rsa`,
  credential stores (`credentials.json`, `.netrc`, `key.properties`), token regexes,
  `.gitignore` matches, and path traversal (`..` or absolute path escapes) from ever
  reaching the downstream prompt builder.
