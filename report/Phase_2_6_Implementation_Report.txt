PHASE 2.6 OBJECTIVE
-------------------
  Introduce a production-grade, deterministic, plan-first Template Customization Engine
  that allows users to customize a resolved or composed template before project
  generation through declarative customization definitions rather than modifying
  the underlying template source. Build the subsystem under the core package with
  clear separation of concerns, supporting customization parameters, presets,
  condition rules, path security checks, and full orchestrator integration without
  mutating the host environment or destroying backward compatibility.

================================================================================
  SUMMARY OF IMPLEMENTATION
================================================================================

1. CUSTOMIZATION SUBSYSTEM (`src/template/customization/`)
   - CustomizationParameter: Defines parameter keys, types (string, boolean,
     integer, select/enum, list), description, default values, allowed values,
     isRequired flags, and feature toggles with strong coercion/validation.
   - CustomizationSchema: Container for parameter definitions, named presets
     (minimal, standard, production), conditional file rules, and path overrides.
   - CustomizationPreset: Named variable profile override presets.
   - CustomizationContext: Resolves variable values following strict precedence:
     Parameter Defaults -> Active Preset Variables -> Explicit User Inputs.
     Bridges resolved variables cleanly into TemplateContext.
   - CustomizationPlan: Immutable preview model exposing active preset, file
     inclusions/exclusions, path overrides, variable values, and JSON export.
   - CustomizationEngine: Evaluates customization logic, conditional file
     rules via TemplateCondition, path override security validation, and template
     rendering application.
   - CustomizationAwareOrchestrator: Unified orchestrator linking the complete
     pipeline: Discovery -> Compatibility -> Resolution -> Composition ->
     Customization -> GenerationPlan.

2. EXCEPTION HIERARCHY EXTENSION
   - Added CustomizationException, CustomizationValidationException,
     CustomizationConflictException, and CustomizationPathSecurityException to exceptions.dart.
   - Ensured zero exposure of file system paths, credentials, or environment details.

3. CLI INTEGRATION (`fps template customize`)
   - Added `fps template customize <template-id>` subcommand under TemplateCatalogCommand.
   - Supports `--version`, `--preset`, `--var key=value`, `--compatibility-policy`, and `--json`.

  _validatePathOverride. Absolute paths (`/`, `C:\`) and path traversal (`..`)
  throw CustomizationPathSecurityException.
- Zero Host Mutation: All customization evaluation and plan building occur 100%

  executions take place during plan preview.
- Determinism: Variable resolution follows strict precedence (Defaults -> Preset -> User Inputs).
  Results are completely deterministic regardless of evaluation order.
