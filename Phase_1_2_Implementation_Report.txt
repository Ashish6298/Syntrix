2. IMPLEMENTATION OBJECTIVES & SUMMARY
--------------------------------------
Phase 1.2 transforms Flutter Package Studio from a command-line driven CLI tool
into an intelligent, terminal-based interactive project wizard experience.
All architecture, APIs, CLI behavior, documentation, logging, and unit tests from
Phase 1.1 have been strictly preserved. The new Wizard module provides modular
components following Single Responsibility and Dependency Injection principles.

3. ARCHITECTURE OVERVIEW & NEWLY ADDED MODULES
----------------------------------------------
The Wizard system is added under packages/flutter_package_studio_core/lib/src/wizard/:
- WizardContext: Stores comprehensive project metadata across 20+ fields.
- WizardTheme: Provides ANSI color palettes with auto-detected plain text fallback.
- WizardQuestion & WizardOption: Supports FreeText, Confirm, SingleSelect, MultiSelect,
  Numeric, SemVer, FilePath, DirectoryPath, and Hidden prompt types.
- WizardValidator: Extends Phase 1.1 Validation Framework for URLs, numbers, email,
  file paths, and package name checks.
- WizardStep: Container for grouping logical questions with execution conditions.
- WizardFlow: Standard sequence definitions with dynamic step branching.
- WizardHistory: Stack-based navigation history for back/undo operations.
- WizardSession: State management with JSON serialization for disk persistence.
- WizardNavigator: Condition evaluation and step indexing engine.
- WizardRenderer: Stream-based CLI renderer supporting custom line readers for tests.
- WizardResult: Sealed outcome type (WizardSuccess, WizardCancelled, WizardFailure).
- WizardEngine: Core workflow coordinator orchestrating step transitions and error recovery.
